# DanMuShow · 多平台直播弹幕面板

同时接 **B站** 和 **抖音** 两个直播间，把弹幕和礼物合成一块矩形面板：

```
┌──────────────────────────────────┐
│ 直播间标题            ● B站 ● 抖音 │
│ 在线观众 1.8万    B站 1.2万 抖音 5688│
├──────────────────────────────────┤
│ 礼物区（占上方约 1/3）              │
│  [头像] 名字 B站  送 🎁烟花 ×10 ¥99│
├──────────────────────────────────┤
│ 弹幕区（占下方约 2/3）              │
│  [头像] 名字 抖音  这波操作太秀了    │
│  [头像] 名字 B站   [表情图] 哈哈哈哈 │
└──────────────────────────────────┘
```

每条消息都带头像、昵称、平台标记。B站是蓝色标记，抖音是红色标记，扫一眼就知道弹幕从哪个平台来。顶部实时显示两个平台的在线观众数。

## 快速开始

### Windows：双击就能跑（不需要懂命令行）

**只有一步前置：装 Node.js。** 打开 <https://nodejs.org/zh-cn/download>，下载 **LTS** 的 Windows 安装包（`.msi`），双击，一路「下一步」。

然后双击项目里的 **`启动.bat`**：

1. 检查 Node.js；没有的话会提示你，并自动打开下载页
2. 首次运行自动装依赖（只有一个 `ws`，很快；直连失败会切国内镜像）
3. 启动服务，并自动打开控制台网页
4. 在控制台填房间号 → 保存

用完直接关掉那个黑窗口就是停止服务。

> 启动脚本是 **GBK 编码**的批处理，专门为了让中文在 cmd 里正常显示。如果你编辑它，请保持 GBK + CRLF，用记事本存成 UTF-8 会变成一堆乱码命令（这就是它之前报 `'��找到' is not recognized` 的原因）。

### 命令行

```bash
npm install
npm start
```

然后打开 <http://127.0.0.1:7801/control.html> 填房间号。

### 先看看长什么样

```bash
npm run demo
```

浏览器打开 <http://127.0.0.1:7801/>，会持续冒出模拟弹幕和礼物，不用连真房间。

## 两个平台怎么填

|  | B站 | 抖音 |
|---|---|---|
| 填什么 | 房间号，如 `21452505`<br>也可以粘 `live.bilibili.com/21452505` | 房间号，如 `123456789`<br>也就是 `live.douyin.com/` 后面那串 |
| 要登录吗 | **不登录也能收弹幕**，但昵称会被打码、表情只有文字（见下） | 不用，程序自己拿 ttwid |
| 要开直播伴侣吗 | — | 不用，和伴侣是否运行无关 |
| Cookie | 建议填 | 选填 |

两边的房间号可以只填一个，也可以都填。都填就是同屏。

### B站 Cookie 为什么建议填

不登录时 B站会做两件事：

1. **部分用户昵称被打码**，显示成 `一***`、`S***` 这种。这是平台行为，不是程序 bug。
2. **没有表情包**，`[花]`、`[赞]` 这类文本表情拿不到图片，只能显示成文字。

填了 Cookie 之后：昵称恢复全名（能查到的会按 uid 反查并自动回填已有弹幕），表情包会加载下来，`[花]` 直接显示成图。

拿法：浏览器登录 B站 → 打开任意直播间 → `F12` → 网络 → 点任意 `api.live.bilibili.com` 请求 → 复制「请求标头」里 `Cookie:` 那一整行。控制台里有「检测登录态」按钮，填完点一下就知道生效没有。

## 放到 OBS 里

1. OBS → 来源 → `+` → **浏览器**
2. URL 填 `http://127.0.0.1:7801/?obs=1`
3. 宽高按你要的矩形填，建议 **560 × 780**
4. 勾上「关闭源时关闭」和「刷新浏览器当场景打开」

`?obs=1` 的**页面底部完全透明**：html、body、面板、分区、分隔线、面板阴影和毛玻璃全部去掉，不需要做色键，图层顺序在 OBS 里自己调。

每条内容自己带一层圆角底，保证压在任何画面上都看得清，又不用给文字加阴影：

- 弹幕正文：一层半透明圆角气泡，只包住文字，不铺满整行
- 平台标记（B站 / 抖音）：保留原来的小圆角色块
- 礼物条：一层偏暖的圆角底
- 在线观众条：`head=1` 时同样带圆角底

鼠标是正常显示的，`?obs=1` 在浏览器里也能正常操作（只是页面背景透明，浏览器会显示成白底，这是正常的——透明只在 OBS 里合成时生效）。

改完 CSS/JS 后不用重启服务（静态文件不缓存），在 OBS 里右键这个源 → **刷新页面** 就能看到。

想调的话：

| 参数 | 作用 | 例子 |
|---|---|---|
| `obs=1` | 透明叠加模式（默认纯透明） | `/?obs=1` |
| `head=1` | 透明模式下也显示头部（标题 + 在线观众） | `/?obs=1&head=1` |
| `bg=1` | 透明模式下保留深色卡片底 | `/?obs=1&bg=1` |
| `nohead=1` | 不显示头部（含在线观众条） | `/?nohead=1` |
| `w` / `h` | 固定面板宽高 | `/?w=520&h=760` |
| `scale` | 字号缩放 | `/?scale=1.15` |

几个常用组合：

- 纯弹幕字幕层：`/?obs=1`
- 带在线人数的完整信息层：`/?obs=1&head=1`
- 录播时想要一块深色板：`/?obs=1&bg=1`

## 翻看漏掉的弹幕

礼物区和弹幕区各自带独立滚动条，鼠标滚轮 / 拖动滚动条都能往上翻。

翻上去之后**新消息不会把你拽回底部**，右下角会出现一个「↓ 有新弹幕 / 有新礼物」的小按钮，点一下回到底部。礼物连击原地更新数字时也不会打断翻阅。

保留条数决定最多能翻多久：默认弹幕 200 条、礼物 30 条，控制台里可以改（弹幕最大 500，礼物最大 100）。超出后从最旧的开始丢，如果你正翻着历史，滚动位置会自动补偿，画面不会跳。

OBS 模式下滚动条和回底按钮不显示（滚动能力还在，只是不画出来），免得录进去。

## 显示选项

控制台里可以调：标题、弹幕保留条数、礼物保留条数、字号缩放，以及是否显示「进场提示」和「点赞/关注」。

同一个人的同一件礼物连续刷，会**原地累加数字**而不是刷屏。

平台状态有三种颜色：绿色＝在直播、琥珀色＝已连上但房间没开播、灰色＝还没连上。房间没开播时弹幕区会提示「等主播开播」，不是卡住了。

## 它是怎么拿到弹幕的

- **B站**：`room_init` 拿真实房号 → WBI 签名请求 `getDanmuInfo` 拿到弹幕服务器和 token → 连 `wss://…/sub`，握手包走 `op 7`，心跳 `op 2`，收到的广播包按 `brotli` 解压后是 JSON。头像在弹幕包里没有，需要按 uid 反查 `x/web-interface/card`，做了缓存和限速，晚到的头像/昵称会回填。
- **抖音**：房间号先走 `webcast/room/web/enter` 换成内部 `room_id` → 用 `webmssdk` 算 `signature` → 连 `wss://webcast…/webcast/im/push/v2/`，收到 `PushFrame` 后 gzip 解出 `Response`，逐条 `Message` 反序列化；服务端要求 ack 时必须回，否则后续不再推送。

### 两个平台都踩过的坑

- **B站礼物已经不是 JSON 了**。现在下发的是 `SEND_GIFT_V2`，里面塞的是 base64 的裸 protobuf（`data.pb`），老的 `SEND_GIFT` 基本不发。只匹配 `SEND_GIFT` 的话礼物会一条都收不到。
- **B站弹幕表情分两种**：大表情是一整条弹幕，图片地址在 `info[0][13].url`，弹幕内容就是表情名；标准表情是文本里的 `[花]`，图片要靠登录后拉表情包才拿得到。
- **B站表情包接口返回的名字自带方括号**（`"[花]"`），弹幕文本里也是 `[花]`，但替换时是按括号里的名字查表的。建表时不去掉括号就永远对不上，最终只能显示成文字——这是「表情只有文字」的根因。
- **抖音的表情弹幕是独立消息** `WebcastEmojiChatMessage`，不是普通弹幕；而且官方字段号公开得不全。这里的做法是用户信息和文字按已知字段取，表情图片在整条 payload 里扫（排除发送者头像，免得把头像当表情），扫不到就退回文字，不丢消息。
- **抖音 proto 里的 `Image` 第 1 号字段被裁掉了**（就是头像、礼物图的 URL 列表），直接用网上流传的静态生成产物头像永远为空。
- **抖音的内部 `room_id` 会随每次开播变**。如果填房间号时对方还没开播，解析到的是旧会话的 id，开播后连上去一个字也收不到。所以每 60 秒会重新解析一次，id 变了就自动重连——这是「抖音明明在播却什么都不显示」最常见的原因。

两边的 protobuf 都是自己按 wire format 解的（`server/lib/pb.js`），schema 在 `douyin-pb.js` 和 `bilibili-pb.js`，字段号都是从真实数据里核对出来的。

## 配置与隐私

`config.json` 里存的是你自己的房间号和 Cookie，**已经在 `.gitignore` 里排除，不会被提交**。

第一次跑的时候直接启动就行，程序发现没有 `config.json` 会自动按默认值生成；也可以手动复制模板：

```bash
cp config.example.json config.json
```

想把配置放到别处（多实例、临时测试），用环境变量指过去：

```bash
DANMU_CONFIG=/path/to/my.json node server/index.js
```

> ⚠️ Cookie 等同于账号登录态，别提交到任何公开仓库，也别截图外发。泄露了就在对应平台退出登录 → 重新登录，旧 Cookie 会失效。

## 自检

```bash
bash tools/selftest.sh 21452505   # 接口 + B站连接 + 弹幕接收
node tools/test-gifts.mjs 120000  # 盯几个热门房间，看礼物能不能解出来
node tools/test-douyin-decode.mjs # 用构造的 protobuf 帧验证抖音解码，不需要真实房间
```

几个前端测试（`test-frontend` / `test-scroll` / `test-obs`）在 jsdom 里跑面板，**不需要浏览器**。jsdom 不是运行时依赖，没装会自动跳过：

```bash
npm i -D jsdom
node tools/test-frontend.mjs   # 礼物、表情、在线观众、昵称回填
node tools/test-scroll.mjs     # 滚动条、淘汰、空状态
node tools/test-obs.mjs        # obs 各种 URL 参数
node tools/test-obs-style.mjs  # obs 透明样式断言（不需要 jsdom）
```

## 已知限制

- 走的是网页端非公开协议，平台改协议可能会失效。B站和抖音都有断线重连，但协议级变更只能改代码。
- 抖音这边**未开播的房间**能连上但收不到消息，面板会显示「未开播」。
- B站昵称打码是平台行为，未登录时**部分**用户的礼物昵称一定是 `X***`；填 Cookie 通常能恢复，但个别开了隐私保护的用户仍然会打码。
- B站头像反查有频率限制，大房间（每秒几十条）可能有个别头像显示成首字母占位，稍后会回填。
- 抖音的礼物/在线人数在未开播房间拿不到，需要房间真正在直播。
